## Three defensible approaches

### A. One-original observation partition under exact-root revocation — recommended

**Scope.** New model/package and command, leaving old states and exports unchanged. Model one original BA, accepted request-bound grant rooted at b, immutable first allow and one debit, one physical allowed gate, one b revocation, and one whole-Store process loss/reopen. c is an unchanged authority coordinate or explicit control, not a second effect whose completion is claimed. No fresh successful gate after loss is needed in the first slice; the revoked fresh-refusal event remains observable. No runtime production change.

**State.** Separate durable original identity/first decision/path/debit/admission ordinal/result, volatile worker opportunity/response, endpoint accepted packet/application/immutable receipt, current exact-root validity, and one shared local owner incarnation. At least two possible authentic result values are required so result truth is not encoded into the model's default. Host death clears local volatile work and changes the shared owner state; it preserves durable local rows and endpoint state. Endpoint accepted work may survive and apply later under the fixed endpoint service contract. Do not implement host death as two chronological A/B crash events.

**Observations.** Define `O_store` from the durable Store plus acknowledged death/Open records; it excludes endpoint internals and unretained responses. Define `O_dossier` as `O_store` plus identity-bound endpoint ingress/commit journal and coherent snapshot at the declared cut. A hypothetical `O_lookup` is not available just because a harness can inspect endpoint SQLite. No synthetic result is installed from forensic knowledge. Distinguish admitted-but-no-observed-contact, ingress-without-application-at-cut, applied-without-local-result, and retained authentic result. Missing/partial external artifacts produce unknown/unsupported, not zero application.

**Candidate new claim.** Under the finite fixed observation contract, one can enumerate `O_store` equivalence classes containing different actual application states even when first allow, exact-root revocation, fresh refusal and debit agree. Complete endpoint evidence refines those classes at a cut without restoring revoked admission or making the result locally consumable. For the no-lookup profile, revoked + lost response + no local result can destroy useful completion despite an actual application. This extends the authority/evidence relation; it does not establish a novel general W3 impossibility.

**Shortest candidate histories (not computed shortest).** Let P be the shared committed/granted/allowed/admitted prefix. Compare P; revoke-b; lose; reopen; fresh-refuse against P; ingress; apply(v); revoke-b; lose-before-record; reopen; fresh-refuse. After hiding world steps and lost response, durable observations should agree; endpoint evidence differs. Another adverse cut is P; ingress-held; revoke-b; lose; reopen; application, demonstrating that death destroys the local opportunity but does not cancel an endpoint-owned packet. A known-result control is P; ingress; apply(v); record(v); revoke-b; lose; reopen; consume(v). Complete enumeration should discover shortest qualifying pairs rather than treating these sketches as measured minima.

**Tradeoff.** Small and falsifiable, fits the existing sealed case, no distributed crash claim. Does not supply reciprocal completion or a full forward relation to the old atomic model. Existing archival cuts may not contain a matched U0-style exact-root pair; generating model pairs is valid model evidence, while concrete pair equality remains unestablished until verified/newly captured.

### B. New two-original split-effect model with one shared owner loss

Keep A-servicing/B-serial reciprocal semantics and b/c separation, but explicitly separate world application, endpoint response and local durable retention; use one owner-loss event for the shared Store. Recompute safety and existence of an authentic two-result consumption suffix with an independent reverse search. The immediate attack is a revoked BA world application whose response is lost: the old `BA.Applied` disjunct predicts completion even though no authentic BA result can reach B, so AB's serial guard remains blocked. A retained-result control should preserve the c-backed suffix.

**New information.** Explains exactly why the old completion predicate cannot survive non-atomicity and gives a corrected finite criterion (or retained counterexample) under a fixed external observation/recovery policy. A pending endpoint packet with eventual response to a dead socket must not count as future local custody.

**Tradeoff.** Stronger compositional result, substantially larger state/transition and proof surface; shared owner loss changes both principals, channel custody and epochs. Adding idempotent re-exposure also requires at least two physical ordinals and a distinct fresh-current-authority check. It must not be sold as a chronological refinement into independently crashing A/B or as backward compatibility of State JSON. A new model rather than mutations to the old model is safer.

### C. Separately authorized receipt-read evidence after mutation-root revocation

Adapt Phase 2C's controlled endpoint contract so an explicit read/adoption authority remains current while b is revoked. Ask whether exactly bound historical application evidence can be selected, and optionally imported, without reauthorizing mutation or reviving b. Track read admission, observation, retention and import as distinct stages; one read opportunity is enough for a first positive slice, but read failure must remain a permitted negative history.

**New information.** The interaction between exact-root revocation and a separately authorized evidence path, including the prohibition on treating an authentic receipt as mutation authority. The mere fact that lookup distinguishes U0/U1 is already Phase 2C.

**Tradeoff.** Larger policy/API/correspondence scope, possibly runtime work. A new endpoint observation channel changes the assumptions and cannot establish recovery under the old no-channel contract. Positive completion requires the right read/import authority, exact original wire and ledger binding, supported result policy, available budget, successful retention and service. `not_found` remains provisional; `found` is not automatically an import or settlement. Owning endpoint contract: `docs/foundational/phase2c/01-endpoint-design.md:7,13,17-29`; conditional completion and exclusions: `docs/foundational/phase2c/02-model-and-argument.md:16-24`.
