## Main conclusion: representation 1 is sufficient at source level

Prefer the packet's first representation: derive selection from the accepted grant's existing `OriginalRequestID`. A separate caller-supplied selection reference or binding object is unnecessary to identify the selection in this runtime. Existing retained data has a unique deterministic request observation ID, its exact consumed sequence, and an indexed history row that must name that observation.

This conclusion has a cost qualification: existing primary/unique indexes do **not** supply an arbitrary-transport admission lookup from the original request. Current v1 already scans all admissions. Avoid claiming that every causal join is indexed today. A narrowly scoped index over existing `admissions.observation_id`, with full descriptor/result validation, is the likely minimal way to avoid that scan in the new format. It is derived indexing, not new authority state or a capability table. Its need and query shape remain to be reviewed; a bounded existing scan is an alternative only if explicitly accepted and measured. Neither representation 2 nor 3 fixes this underlying admission lookup problem by itself.

### Exact derivation and required guards

Start only from the grant chosen in the service's retained `AuthorityUse.GrantID`, and then its `DelegationClaim.OriginalRequestID = q`:

1. Load the actual q intent by `intents.id` and bind descriptor/index identity. Require ordinary message, exact holder generation/revision, destination A's exact generation, real commitment before the relevant prefix, and original allowed source authorization. Accepted delegation already checks these at issuance, but the durable checker/gate must preserve the original-to-record join.
2. Derive `oID = identity("observation", "message", q.ID)`. `messageDescriptor` fixes `LogicalID=q.ID`; `observationFor` fixes this ID independently of arbitrary transport ID. Load `observations` by its PK, require its indexed subject/generation and descriptor Run match service Run, canonical descriptor, exact ordinary-message provenance/source, and equality with the observation derived from authentic q (not equality with arbitrary application registers or payload request_id text).
3. Require non-NULL `observations.consumed_sequence=c`, with `0 < c < service.Sequence`. The strict comparison is with the service **commit**, not merely first decision or gate: selection after service emission cannot repair it. Load `history` using PK `(service.Run.Subject, service.Run.Generation, c)` and require `selected_observation=oID`. Retain and validate corresponding execution fact before the service execution fact, and both before the authority prefix. Check the selected row's actual program/reducer validity through existing full ledger validators. History `source_revision` should be checked against the declared preserved identity/revision policy; the positive domain does not cross an ownership/revision mutation.
4. Require genuine accepted message admission to the same Run for this exact o/q, and validate its descriptor against `messageDescriptor(q, actual transportID)`, all indexed/JSON identities, `Accepted`, Bound, ObservationID and `observationFor`. No search for an arbitrary previous same-peer message. Multiple genuine delivery attempts can legitimately share the same logical observation; do not assume one admission per q.
5. Continue existing exact grant/service/tuple/root comparisons and prefix-local root/revocation policy. The accepted grant must precede the authority decision, but need not precede request selection where the declared contract permits select-before-grant. Retained current grants/results cannot justify a past decision.
6. Populate existing `EffectAuthority.RequestObservationID` and `RequestConsumedSequence` with actual o/c. Those fields already exist; no new service metadata is needed. First refusal remains immutable. A fresh physical gate rechecks the same selected grant/root, original allow and original debit, current owner/source/scope and revocation.

Missing observation/selection must produce the frozen safe-refusal semantics, while structurally contradictory stored identities are corruption. Currently v1 uses `authority_request_not_selected` for missing predecessor selection and `authority_request_not_admitted` for the ready-vs-original mismatch. The new profile must specify its reason vocabulary and precedence without relabelling old witnesses.

### Why the alternatives lose on inspected evidence

Representation 2 would store a selection reference that the runtime can already derive exactly from q/o. It adds a public encoding/authoring obligation and another forged or stale claim to verify. It could be useful for a future language with multiple independently identified observations/selections per original, but that is not this model: logical message observation ID is deterministic and one observation is consumed at most once.

Representation 3 adds state/transitions without a demonstrated expressive gap. Existing grant, admission, observation and selecting history suffice. A binding operation would also alter future service sequence locators and resource/trace vocabulary, increasing this slice's construction burden.

Attack representation 1 with two same-peer requests of equal payload: q and q2 still have different intent and observation IDs. Selecting q2 after q must not change service binding to q. Selecting only q2, or substituting its grant, must not satisfy q. A last-receive register approach fails this test; the exact-q derivation does not depend on that register.

## Public construction: static padded fixtures are feasible in principle

`examples/delegation/reciprocal.go` uses public runtime/schema packages and canonical retained-program Artifact JSON; its local wire structs avoid private executor imports. Public `runtime.Artifact`/Provision supports the same construction for a new finite example. It already computes locators with json.Marshal `[subject,1,sequence,0]`, creates `DelegationClaim` before programs are hashed, serializes the exact claim in B's ordinary lifecycle instruction, and hashes each final program's bytes.

For the equal-length receive swap, A service remains sequence 4. This first pair isolates adjacency; do not change grant/service locator.

For a finite deterministic padding stretch, construct a **new** provision: declare the actual number of committed instructions on its service path, calculate the new canonical service sequence, embed that locator in the genuine B-issued claim and all relevant copies, update downstream branch PCs and reply/service locator references, serialize and hash the final programs, then Create. `program.go:Reduce` executes one instruction per committed reduction; successful emit uses actual committed sequence and ordinal zero. Local set/copy instructions and known/equal-length forward branch paths therefore have a calculable locator without private inspection, SQL edits or grant forgery. Program hash is not part of operation ID, avoiding a hash self-reference. Logical root locators are known before namespace creation.

This remains source reasoning, not a demonstrated new authoring API or executed construction. The existing Reciprocal Options has no padding option. Its unexported wire helper types mean the clean public example may introduce its own small builder or extend the same example package before provisioning; do not edit an already-created Store or repair retained grants.

Open construction questions:

- Forward branches with different path lengths do not have one service sequence known independently of the path. First qualify known paths/equal-length alternatives, or honestly record the need to provision a grant for the actual planned locator. Do not call source PC+1 a sequence when branches skip instructions.

## Prospective discriminators and falsifiers

Freeze predicted verdicts before implementing:

- Adjacent selection→service: still allow in v1 and candidate with exact authority.
- Equal-length request→ready→service: preserve v1 refusal; candidate allows only exact earlier q selection. Execute full reciprocal result path separately from authority allowance.
- Zero/one/multiple local steps and forward branches: exact newly granted locator; preserve q/o/c, program identity, tuple/root/source eligibility and adequate bounds. Wrong old locator must still refuse.
- q delivered but not selected; q selected after service emission but before decision; q selected in another generation; forged consumed_sequence or selected_observation; q2-only selected; equal payload; latest receive substituted: all must fail causal binding.
- Selection before grant issuance and after grant issuance: allowed only where grant accepted before first authority decision; service first refusal before grant remains sticky after grant/reopen.
- Grant accepted/current at final snapshot but not historical first decision; revocation after selection before fresh gate; pre-revocation allow with post-revocation retained result: retain correct prefix-specific distinctions.
- Exact tuple/root/revision/service mutation, Cartesian dimension borrowing, result-as-authority, alternate-path fallback: preserve original refusals.
- Crash before selection commit versus after commit; before service commit versus after commit/before decision; after allow/before new gate; result-before-consumption; two owner losses. New epoch may change; original q/o/c/grant/service/debit must not.
- Coherently rehash an attempt/reservation away from original q/service; gate must reload immutable operation and original request rather than trust consistency of the forgery.
- Mutants deleting c<service.Sequence, substituting latest selected observation, omitting generation equality, and skipping fresh-gate revocation must be killed by semantic assertions, not parser failures or checker crashes.
