## Why the proposed witness is executable

- The common **closed, pre-execution** seed and exact reuse of the two endpoint URLs eliminate the namespace/program/root/wire identity differences without rewriting captured evidence. Separate fresh endpoint stores and sequential, fully reaped endpoint processes make these alternative histories of one initialization. This construction does not establish concurrent cloned ownership or independent deployment equivalence; the contract correctly excludes those readings.
- Frozen `internal/executor/external.go` makes the pre-call observer synchronous and checks its returned error before `client.Do`. `externalWork` contains copied data and the transport worker never accesses the Store. Its completion is accounted by the scheduler. Thus a correctly implemented independent worker hold can prevent the zero call while permitting the applied call without directly changing local retained state.
- Frozen `internal/executor/runner.go` reaches `runner.waiting/in-flight` only after its ordinary delivery, ready-reduction and root-settlement pass finds no progress. The callback precedes completion reception/accounting. Holding this scheduler callback in both branches closes the scheduler-progress race left by a worker-only cut.
- Frozen `internal/boundary/boundary.go` confirms that the ordinary selected pauses share a mutex. Two ordinary filters would deadlock the intended acknowledgment protocol. The plan correctly calls for an independent worker pipe/channel and ordinary scheduler observer; forwarding `external.authorized` before notifying pre-call is necessary to obtain the exact sole `InFlight` authorization.
- Frozen `internal/testcmd/alan-resource/main.go` journals commitment before the post-commit callback and emits the successful receipt only after that callback succeeds. Cancellation may end that callback with an error, but cannot turn it into a successful receipt release. Consequently, the plan should certify withholding successful receipt, as its contract does, rather than uninterrupted occupancy of the endpoint callback.

These source facts make equality plausible, not guaranteed. Initial scheduler/fact insertion order can still differ. Frozen `internal/executor/inspect.go` exports rows in `rowid` order and exposes descriptor/program BLOBs as strings. The contract deliberately retains that order and string content. A mismatch is an experimental result; it is not grounds for sorting, parsing-and-reencoding retained descriptor strings, alpha-renaming, or selecting a later successful retry.

## Implementation obligations already within the approved scope

1. Make the owner context and scheduler barrier lifetime explicit. The historical owner has a 15-second context deadline and the inherited observer returns on cancellation/EOF. Merely recording no scheduler release does not establish that the scheduler remained held through death. Use an appropriate test-only lifetime/abort protocol and retain exit/control evidence; reject early return, timeout or unconfirmed kill as apparatus failure. No production change is needed.
2. Task 1 must define a complete event/schema and write durable controller ordering before Task 2 implements checks. Bind every worker acknowledgment, scheduler acknowledgment, release and confirmed death to the actual owner configuration; bind endpoint readiness/journals/snapshots/wait to their own process and store. Controller receipt order and pipe causality suffice; wall-clock timestamps alone do not.
3. Preserve failures through cleanup, including failure before both branches finish. Seal what exists with an explicit incomplete/failed status. A partial dossier must never be treated as a zero world. Cleanup must kill/reap owners before releasing any worker pipe.
4. Compare the entire parsed outer `inspect.json` and final `run.json`, retaining unknown/additional fields for comparison while separately enforcing the frozen expected schema. Preserve integer precision and reject duplicate keys, including in embedded semantic JSON when validating those descriptors. Check exact renewal independently of cross-branch equality: equal corruption on both sides is not a valid pair.
5. Keep two trust statements distinct: sealed-byte custody and source-conditioned raw/protocol consistency. A JSON-only checker can independently validate declared exports and joins and hash SQLite as opaque bytes; it cannot independently prove that arbitrary JSON was extracted from arbitrary database bytes. The frozen producer/capture procedure supplies that connection. Do not describe the JSON checker as independently revalidating SQLite contents.
6. Fix endpoint coverage/cut evidence in Task 1's schema. Final-only absence is insufficient by itself. The held zero pre-call, confirmed death, fresh refusal and complete process interval provide the causal argument; the applied post-commit acknowledgment anchors application before death. Reject extra contacts and unclassified/truncated records. Capture-only inspection must operate on disposable complete copies, never archived databases.

These are concrete implementation and review checks, not requests to expand scope or require a new user decision. The contract already requires their substantive outcomes.
