# Phase 3B.7 capture reconnaissance

## Finding

The frozen v2 runtime exposes the selected BA worker immediately before its first HTTP call. It also exposes the scheduler after ordinary progress has drained while that worker is still in flight. A single new integration test and a small test-only child wrapper can use both existing observation points. No production runtime, endpoint implementation, or historical capture changes are required. The stronger matched experiment uses a common closed seed and a common scheduler stopping point before releasing the selected worker only on the applied branch. This is a proposed protocol from source inspection. No test or runtime experiment was executed.

Runtime source references below are pinned to Git commit `5b4662fd682a220ca3065b15e86672b7e56567e7`, verified tree `44af03133ac7ba75fb6f6f8dc36629ed4cf52d98`. The research contract requires an accepted exact request-bound grant, historical allowance and debit, initial allowed gate, one shared owner loss/reopen, exact b revocation with c preserved, and a fresh refusal before comparing local observations. The old runtime relation lacks the pre-call v2 half. See `docs/foundational/phase3b6/01-contract.md:44–67`, `04-correspondence.md:15–25,45`, and `07-results.md:37–41`.

## Match the durable stopping point before splitting the branches

Killing the zero branch as soon as its worker reports pre-call can race the scheduler. Run can deliver ordinary work and commit ready reductions after spawning the worker. The historical applied producer's generic `runner.waiting/in-flight` ack can also race `external.authorized`: the inherited observer adds an authorization to `InFlight` when it observes that worker event, and the runner may get to its callback first. See `internal/executor/runner.go:113–174,224–275` and `internal/boundary/boundary.go:73–95`.

Proposed child protocol:

1. Reuse the existing public owner `runtime.Open` and initial backup/open artifacts before `Run`, following `internal/durabletest/phase3b4_cuts_test.go:21–54`. Use the same Run limits in each branch, one test-only observer and separate holds for the worker and scheduler.
2. Pass the worker's preceding `external.authorized` event into the inherited boundary observer to register the selected authorization. When `dispatch.admitted/pre-call` matches exact BA, record the original process configuration and event, encode and fsync before signaling an in-child channel or writing a worker ack. Hold that callback independently of the scheduler. A dedicated inherited release FD after the conventional fd3 acknowledgment/fd4 release pair suffices. A context-aware timed read permits cancellation to fail the barrier. Only explicit worker release permits the worker to proceed.
3. When the scheduler reaches `runner.waiting/in-flight`, wait for the worker's recorded pre-call signal without holding the log mutex. Invoke the ordinary inherited fd3/fd4 scheduler barrier after that channel fires. The controller must verify that the runtime scheduler ack names exactly the selected authorization in `InFlight`. This callback is reached only after pending ordinary work, ready commit and root settlement processing find no progress on the current turn and at least one worker is active. It occurs before the scheduler's receive/account select (`internal/executor/runner.go:245–288`).
4. Await the scheduler ack on both branches while the BA worker is still held. On zero, never release either original runtime hold. On applied, release only the worker, wait for endpoint b's exact `resource.applied/post-commit` ack, and withhold both the scheduler release and endpoint successful-response release until confirmed runtime death. The runtime cannot account a completion or take another scheduler turn during the split. On both branches use the existing `child.kill` (`internal/durabletest/crash_test.go:158–171`), which requires validated acknowledgment, sends SIGKILL, waits and validates the signal. Record release/ack/wait ordering as an explicit controller transcript.
5. Require the predicted stopped states, both original epochs 2, A at sequence 4 and B at sequence 5, exactly one selected allowed admission at original epoch and ordinal 1, no local BA result/custody, and complete identical stopped raw inspections across the pair. Independently compare the observed prefix even though the callback/source argument is favorable. A source assertion about all schedules or ordinary worker work would exceed the evidence.

The old `bindingOwner` and `phaseTestProcess` supply ordinary subprocess/open/ack code (`phase3b4_cuts_test.go:21–109`, `reconciliation_helpers_test.go:35–85`), but their single inherited hook does not implement simultaneous holds. `boundary.FromEnvironment` accepts an array of filters, yet serializes all selected pauses under one `pause` mutex held through the wait (`internal/boundary/boundary.go:42–65,87–140`). Two array filters cannot solve this: one selected hold blocks the other's acknowledgment. A minimal test-only child can copy the small existing owner setup and reuse public Store APIs and helpers, or overlay only that test file while leaving its existing entry point behavior intact. Use a separate worker channel/pipe and retain the ordinary observer for the scheduler and active authorization tracking. The worker event and scheduler ack require an explicit identity join because the old observer writes plain boundary logs before enrichment by the inherited barrier (`phase3b4_cuts_test.go:57–84`). The custom pre-call record should explicitly retain controller-provided scenario/token/Store plus actual PID, alongside the original semantic fields.

The endpoint emits its ack after application commits and after journal Sync. At `internal/testcmd/alan-resource/main.go:149–183,194–232`, journaled ingress contains exact request bytes, commit evidence contains the authentic receipt, and successful HTTP response encoding follows a successful post-commit barrier return. `internal/fixture/resource.go:154–216` commits the contacts and application transaction before the handler ack. The main endpoint profile used here is the historical idempotent HTTP fixture on `/apply`. Do not add `--receipt-ledger`, change `--response-mode`, or infer a non-idempotent retry theorem. The endpoint wait inherits request cancellation (`main.go:214–218`), so it can return an error after timeout or client death. No successful receipt can cross before controller release. Avoid a claim of continuous endpoint barrier occupancy. A post-wait release attempt follows historical producer lines 204–213, and its outcome can be retained separately.

## Preserve exact concrete identities

Choose a common closed v2 seed fork before either experiment executes, with identical endpoint URLs:

1. Start branch zero's fresh endpoints on two auto-assigned, distinct literal loopback addresses and retain their actual ready URLs. Produce one v2 provision/manifest using those URLs, call public `runtime.Create` once, close it and make two independent byte copies of its complete quiescent database file set before opening either copy. Reuse `reciprocalCopyDB` for main/WAL/SHM where present (`internal/durabletest/phase3b3_runtime_test.go:89–98`). Do not hardlink, copy a lock file, or run the seed. Record per-file seed and copy digests before either child starts. Keep seed and branch runtime paths distinct.
2. Run branch zero, then terminate/wait its two endpoints. Start branch applied's independently initialized endpoint databases and journals using the exact same listen addresses and verify byte-identical ready URLs with fresh PID/token/Store identities. The endpoint CLI already supports `--listen` and returns the actual URL (`internal/testcmd/alan-resource/main.go:31–37,71–98,235–249`). The existing helper hardcodes `127.0.0.1:0` (`internal/durabletest/phase3b3_cuts_test.go:21–39`); parameterize a test-only helper or build a small companion using its readiness and cleanup protocol. Treat binding failure/URL mismatch as apparatus failure. A bound address is currently supplied by the fixture, avoiding a separate reserve/release race before the first branch. Never share endpoint SQLite state or run both clones concurrently against the same listener.
3. A common seed matters: Create makes a fresh random namespace (`internal/executor/store.go:327–332`). External key uses namespace and operation ID, with authorization epoch/ID retained in the wire (`internal/executor/external.go:89–96`, `internal/executor/store.go:982`). Endpoint URLs occur in exact root permissions, program bytes, claims and intent targets (`examples/delegation/reciprocal.go:112–124,136–159`). Open locks by canonical database path, validates retained state, takes its namespace and advances every open run exactly once (`internal/executor/store.go:127–176,605–618,654–697`). The pre-run fork is an apparatus assumption for two counterfactual executions with identical initial local state. It creates no extra owner loss, does not exercise owner migration, and says nothing about two live writers or two stores sharing a world. Inside each branch there is exactly one original child SIGKILL and one reopen of the same working path. Same physical pathname reused sequentially from a seed is possible but unnecessary; separate paths and digest-checked copies make accident isolation simpler.
4. Preregister exact complete final raw inspection equality per normal/race pair, with no normalization. Comparing raw JSON bytes in this same-toolchain setup covers namespace, key version, Settings, Tables, Roots, and any present ReceiptEvidence. `internal/executor/inspect.go:15–23,97–141` shows the exposed surface and row ordering. Comparing only `research/delegationcorrespondence/wire.go:311–317` drops the optional top-level ReceiptEvidence field, so prefer entire `inspect.json` bytes as the strong observation or use a full decoder that preserves every field. Also require full stopped equality and independently derive equal `O_store` values as a secondary check. Physical DB file-byte equality at final is a different assertion about SQLite representation. Preserve real files and digests, and report any observed inspection divergence as a falsifier.
5. Independent `Create` calls with default dynamic endpoints would require an explicit typed identity bijection over independent namespaces, full b/c root tuples, target URLs, concrete programs, wire keys, dependent grants/gates/digests, and selected custody. Equal model `StoreView` alone cannot establish those concrete joins. The closed seed removes this avoidable abstraction cost. Match branches within each producer mode. A separate fresh seed per mode is sufficient and makes no assertion that normal and race experiments share the same namespace.

## Test-only build and qualification hazards

- Materialize the pinned runtime objects into disposable scratch storage with immutable production inputs and add one `//go:build integration` `package durabletest` test file there, or use an explicit `go test -overlay` mapping to a virtual file in that package. Scratch insertion of the sole new test is simpler to audit. Preserve baseline tree identity, exact overlay/test file SHA-256, test file list, complete source inputs, toolchain/GOOS/GOARCH, argv and relevant environment. Never claim a new executable tree equals the frozen Git tree when it includes a test overlay.
- The old `reciprocalSources` shells out to `git rev-parse HEAD` at the root inferred from `runtime.Caller`, reads source files via disk globs, writes a historical allowlisted Go environment and exports programs (`internal/durabletest/phase3b3_runtime_test.go:455–503`). Bare `git archive` extraction has no Git metadata. A detached disposable checkout/clone gives the expected HEAD, but `go -overlay` does not make replacement bytes visible to those direct file reads. Keep explicit overlay provenance and check physical pinned source hashes, or use a standalone test-only index/provenance writer against an archive extraction. Do not retag new evidence with the historical archived producer identity alone. Do not use `-trimpath` with the old source helper without accounting for its caller-path assumption.
- Reproduction entry point proposal: `ALAN_PHASE3B4_EVIDENCE=ABS_RAW_DIR go test -json -count=1 -tags=integration ./internal/durabletest -run '^TestPhase3B7MatchedLoss$'`; add `-race` with a separate output root for the race mode. Pin the actually used toolchain, baseline `go.mod:3` requires Go 1.27.3, and record the compiler's actual version. Use the offline environment and task-specific existing caches once checked. Existing `binaries` builds the exact endpoint command from the module root and propagates race mode (`internal/durabletest/crash_test.go:21–60`, `race_on_test.go:1–5`, `race_off_test.go:1–5`). Its owner helper invokes the parent test executable with exact `-test.run`, sets `ALAN_PHASE2_CHILD`, `ALAN_PHASE2_DB`, `ALAN_PHASE2_ENDPOINT`, `ALAN_PHASE2_MODE`, and `ALAN_BARRIER` with fd3/4 (`reconciliation_helpers_test.go:35–85`). The old owner adds `ALAN_PHASE3B4_CHILD=1`, `ALAN_PHASE3B4_OUTPUT`, `ALAN_PHASE3B4_MANIFEST`, optional `ALAN_PHASE3B4_REVOKE` (`phase3b4_cuts_test.go:98–108`). A new child mode or release FD should have explicit task-specific configuration. Clear inherited barrier/child overrides and avoid secrets in logs.
- Never hold the observer log mutex across a selected pause or a channel wait. Barrier errors/EOF must fail closed. The old child outer timeout is 15 s and worker HTTP timeout is 5 s (`phase3b4_cuts_test.go:25,91`), and `reciprocalAwait` times out at 40 s and validates PID/config/selector fields (`phase3b3_runtime_test.go:347–364`). Bound all waits, make timeout a trial failure if it invalidates the selected cut, and avoid timed sleeps for ordering. If the worker release pipe or scheduler observer fails, capture the failure. An applied endpoint can cancel after ack without producing a successful result. A canceled unreleased worker cannot call the endpoint, but a completed/canceled scheduler cut needs explicit evidence before acceptance. The stale generic `runner.waiting` ack race is handled by waiting for pre-call only after registering `external.authorized`.
- Close/kill/wait safely on every failure; preserve logs before TestMain removes its binary directory (`crash_test.go:24–29`). `reciprocalEndpoint` uses a blocking readiness decode and validates PID/Store/token (`phase3b3_cuts_test.go:40–75`); the fixed-URL helper should bound readiness and retain startup errors. Keep per-mode result directories unique, freeze completed files only after all relevant writes and waits, and record normal/race results independently. Never modify historical artifacts or rewrite captured fields to obtain equality.
